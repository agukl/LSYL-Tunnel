# Runtime Performance Compatibility Design

## 目标

在不升级隧道协议、不修改配置格式、不改变现有四类业务日志文件及字段的前提下，降低服务端认证与状态维护开销，减少 Windows 客户端重复工作，并收口虚拟转发辅助进程数量。

## 全局约束

- 隧道 `protocol_version` 保持为 2，旧客户端与新服务端继续兼容。
- 服务端和客户端 YAML 结构不变，不增加配置项。
- 请求、业务、入口流量、数据流量四类 JSONL 文件名、字段和同步落盘语义不变。
- 服务日志中的 `request_log`、`business_log`、`entry_traffic_log`、`flow_traffic_log` 前缀和 JSON 内容不变。
- 不实现短期认证令牌、连接复用或隧道多路复用。
- Win7 Lite 仍使用 Go 1.20、`GOARCH=386` 构建，不增加虚拟 IP 能力。

## PBKDF2

服务端密码哈希继续使用 `pbkdf2-sha256:<iterations>:<salt>:<key>`。内部派生实现改用 Go 1.25 标准库 `crypto/pbkdf2` 和 SHA-256，不改变默认 210000 次迭代、16 字节随机盐和 32 字节结果。

现有 `plain:` 与 `sha256:` 兼容验证路径保持不变。标准库调用失败时，生成密码返回错误，密码验证返回失败，不允许降级到其他算法。

测试必须使用固定盐、迭代次数和预先记录的旧实现结果证明字节级兼容，并覆盖已有编码哈希的正确密码和错误密码验证。

## Windows 客户端 TLS 与启动认证

`Client` 在启动时创建一次只读 `tls.Config`，后续业务连接、反向控制、反向数据流、健康检查和转发检查全部复用。`tls.Config` 创建失败必须在监听端口或启动虚拟 helper 前终止启动。

保留现有 `Start` 行为，供没有预认证的调用方使用。新增已验证启动入口，接收登录成功返回的服务端版本，将健康状态初始化为正常，并在 30 秒正常周期后才执行首次健康检查。

标准 Windows GUI、Win7 Lite 和 CLI 先完成一次登录验证，再进入已验证启动路径。GUI 仍使用登录响应中的凭据公钥保存本地凭据。启动后不再立即发出第二个健康认证请求。

手动刷新、后续健康检查和每条业务流仍按原协议独立认证，本次不改变服务端授权边界。

## 虚拟转发会话

客户端先为每条虚拟规则分配独立随机回环监听端口，再将全部有效规则一次性传入一个虚拟转发会话。单次连接最多启动一个 anchor、一个管理员 helper 和一个 WinDivert 句柄。

helper 启动成功后同时激活全部虚拟规则。管理员授权取消或 helper 启动失败时，关闭全部已准备的虚拟监听并将全部虚拟规则标记为不可用；普通正向和反向规则继续运行。若没有任何其他可用规则，沿用现有“授权取消不阻止连接”的行为。

共享 helper 运行中断时，全部虚拟规则进入监听失败状态并关闭各自回环监听，普通规则和客户端主进程继续运行。客户端关闭时共享会话只关闭一次。

## 最近事件环形缓冲

最近事件使用固定容量环形缓冲，容量来自现有 `runtime.recent_events`，默认 500。追加事件为 O(1)，覆盖最旧事件时不分配和复制整个切片。

状态接口快照返回独立切片，顺序保持“从最旧到最新”，与当前管理台消费方式一致。容量未满、容量为 1、覆盖回绕和并发快照均需测试。

## 日志单次序列化

每条日志记录只调用一次 `json.Marshal`。同一字节结果先按现有前缀写服务日志，再追加到对应日期 JSONL 文件。JSONL 写入器新增接收已编码 JSON 的内部入口，并继续持有原有文件互斥锁、日期轮转和同步写入行为。

入口异常日志继续通过现有有界异步队列进入单写入协程；不改变队列容量、丢弃统计和关闭排空逻辑。

测试必须比较服务日志 JSON 与 JSONL 行的字节内容，并验证四类日志字段和日期文件路径不变。

## IP 状态清理

失败追踪器新增 IP 时仅创建状态，不再先执行全表清理。只有状态数量达到上限时，才先清理过期记录，再按现有规则驱逐最旧的非封禁记录。

连接限制器沿用容量触顶时清理和驱逐的逻辑。连接限制快照、失败追踪统计和监控 `/status` 不再触发全表清理或状态文件写入，仅返回当前内存数据。两个追踪器的定时清理协程继续按现有配置运行。

对已存在 IP 的访问仍局部裁剪其速率窗口或失败时间序列，保证单 IP 限制准确。测试使用可控时钟证明：普通新增和快照不会扫描删除其他 IP，定时清理和容量触顶仍会删除过期状态。

## 验证

- PBKDF2 固定向量、兼容哈希和分配基准通过。
- 客户端单元测试证明 TLS 配置只构建一次，已验证启动不会立即健康认证。
- 两条以上虚拟规则只启动一个共享会话，共享失败会停止全部虚拟规则。
- 最近事件在回绕后顺序正确，日志服务输出与 JSONL 内容一致。
- 连接限制器和失败追踪器仅在定时或容量路径执行全表清理。
- `go test ./src/...` 通过。
- Win7 Lite 构建通过。
- Windows 服务端、标准客户端和安装包发布构建通过。
