# Android 增强后台模式设计

## 背景

Android 客户端当前已使用前台服务承载本地监听和隧道转发。真机 ADB 检查确认：

- Activity 可见时，进程处于 `TOP` 调度状态；
- Activity 退到后台后，服务仍是有效的 `FGS`，通知、监听端口和网络权限均正常；
- 后台网络策略最终未阻断隧道，但进程会从前台调度组降到前台服务调度组；
- 当前 Doze、电池优化和厂商后台策略仍可能降低长连接稳定性。

因此性能和稳定性分级定义为：

`前台 >= 增强模式 >= 普通后台`

增强模式的目标是让用户主动用额外耗电换取更接近前台的后台稳定性，但不伪造可见页面，也不承诺获得系统 `TOP` 优先级。

## 目标

- Android 主页面增加持久化的“增强后台”开关。
- 普通后台保持现有行为和功耗特征。
- 增强模式从发起连接到断开期间持续持有 CPU 唤醒锁。
- Android 10-13 在 Wi-Fi 下持续持有后台有效的 Wi-Fi 高性能锁。
- Android 14 及以上不宣称后台 Wi-Fi 性能锁生效，依靠 CPU 唤醒锁和电池优化豁免维持后台运行。
- 首次开启时请求用户忽略系统电池优化。
- 用户拒绝电池优化授权时仍允许开启增强模式，并明确显示授权未完整。
- 系统恢复服务后按持久化设置恢复增强资源。
- 所有退出路径可靠释放资源。

## 非目标

- 不通过悬浮窗、透明 Activity、画中画或高频心跳伪造前台状态。
- 不改变协议、服务端、配置文件或转发规则格式。
- 不宣称增强模式等同于系统前台调度。
- 不尝试绕过厂商系统的用户授权界面。

## 方案比较

### 方案 A：全连接周期资源增强（采用）

前台服务叠加 `PARTIAL_WAKE_LOCK`、电池优化豁免请求，以及 Android 10-13 上后台有效的 Wi-Fi 高性能锁。稳定性最强，符合用户明确选择的全周期增强语义；代价是连接空闲时也会增加耗电。

### 方案 B：仅业务流期间增强

只在存在活动转发流时持锁，空闲功耗更低，但业务流刚建立、网络恢复及系统调度切换仍可能处于普通后台状态，不符合“连接期间始终增强”的要求。

### 方案 C：仅请求电池优化豁免

实现简单、功耗较低，但无法直接保持 CPU 和 Wi-Fi 无线电活跃，厂商差异较大，增强效果不足。

## 组件设计

### 后台模式设置

新增独立的持久化设置，至少包含：

- `enhanced_background_enabled`：用户是否启用增强后台；
- 电池优化授权状态不持久缓存，每次通过 `PowerManager.isIgnoringBatteryOptimizations()` 读取系统真实状态。

设置与运行快照分离。切换设置不会修改配置文件，也不会重建转发规则。

### 资源控制器

新增单一职责的资源控制器，由 `TunnelForegroundService` 持有：

- 非引用计数的 `PARTIAL_WAKE_LOCK`；
- Android 10-13 使用非引用计数的 Wi-Fi 高性能锁；
- 幂等的 `acquire()`、`refreshNetwork()` 和 `release()`；
- 记录每种资源是否实际持有，重复命令不得重复获取或错误释放。

CPU 锁在增强模式连接生命周期内始终持有。Android 10-13 的 Wi-Fi 锁仅在当前默认网络具备 Wi-Fi 传输能力时持有；切换到移动网络时立即释放，切回 Wi-Fi 时重新获取。

从 Android 14（API 34）起，公开 API 会把 `WIFI_MODE_FULL_HIGH_PERF` 自动替换为 `WIFI_MODE_FULL_LOW_LATENCY`，后者只在屏幕点亮且应用位于前台时生效。增强后台不得在这些版本上获取并展示一个实际无效的 Wi-Fi 性能锁，也不得使用非公开 API 绕过限制。

### 服务生命周期

资源获取点：

1. 服务处理连接或系统恢复命令；
2. 持久化设置为增强模式；
3. 前台通知已经建立；
4. 隧道仍是用户期望运行状态。

资源释放点：

- 用户断开；
- 连接发生不可恢复失败并清除期望运行状态；
- 服务销毁；
- 用户在连接期间关闭增强模式；
- 配置删除或替换导致服务停止。

系统因资源压力销毁服务时，`onDestroy()` 先释放锁。若随后按 `START_STICKY` 恢复，服务重新读取设置并获取资源，不依赖旧进程内状态。

### 网络变化

现有默认网络回调继续负责连接恢复，同时在 Android 10-13 通知资源控制器更新 Wi-Fi 锁：

- Wi-Fi 可用：增强模式下按系统版本获取可生效的 Wi-Fi 锁，再执行既有恢复检查；
- Wi-Fi 离开或切到移动网络：释放 Wi-Fi 锁，CPU 锁不变；
- 无网络：释放 Wi-Fi 锁，保持 CPU 锁等待网络恢复。

网络回调不得新增高频轮询。

## UI 与授权

主页面操作区增加 Android 原生二态开关“增强后台”，默认关闭。开关状态持久保存。

开启时：

1. 保存增强模式；
2. 若系统尚未忽略本应用的电池优化，打开系统授权页；
3. 用户返回页面后重新读取系统状态；
4. 已连接时立即通知服务获取增强资源，无需断开重连。

关闭时立即通知服务释放增强资源，但不终止当前隧道。

授权状态文案：

- 已开启且已豁免：`增强后台已开启`；
- 已开启但未豁免：`增强后台已开启，系统限制未完全解除`；
- 已关闭：不显示额外警告。

授权被拒绝、授权页面不可用或厂商系统不支持直接请求时，开关仍保持开启，并回退到 CPU 锁以及受支持系统上的 Wi-Fi 锁增强。

## 权限与兼容性

Manifest 增加：

- `android.permission.WAKE_LOCK`；
- `android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。

最低版本仍为 API 29。Android 10-13 使用 `WIFI_MODE_FULL_HIGH_PERF`；Android 14 及以上不获取该锁，因为平台会将其替换为仅在屏幕点亮且应用前台时生效的低延迟锁。代码只依赖公开 API，并处理获取失败。

该客户端为用户主动启动的持续加密隧道，电池优化会直接破坏核心长连接功能；直接请求豁免仍必须由用户确认。增强模式可能产生明显额外耗电，属于用户显式选择。长时间锁屏仍保持连接时，系统还可能提示应用存在较长的唤醒锁占用；这是全连接周期增强的已知代价。

## 错误处理与安全释放

- 获取任一锁失败不能导致隧道连接失败；运行状态显示具体增强资源未完全生效。
- `release()` 在未持锁、重复调用和部分获取成功时均安全。
- 不在日志中记录配置、凭据或目标地址。
- 不新增周期任务、后台心跳或长期定时器。
- 服务停止和进程正常退出后不得残留系统锁。

## 测试

单元测试覆盖：

- 设置默认值、持久化和切换；
- 资源控制器幂等获取与释放；
- Android 10-13 上 Wi-Fi、移动网络、无网络之间切换；
- Android 14 及以上不获取无效的后台 Wi-Fi 性能锁；
- 增强模式连接、关闭开关、断开、失败和服务销毁路径；
- 电池优化已授权、拒绝和授权页不可用；
- 普通后台不获取任何新增资源。

真机 ADB 验证覆盖：

- 普通后台仍为 `FGS` 且无应用唤醒锁；
- 增强模式后台可从 `dumpsys power` 观察到 CPU 锁；Android 10-13 还可从 `dumpsys wifi` 观察到 Wi-Fi 锁；
- Android 10-13 切换到移动网络后 Wi-Fi 锁释放；
- 关闭开关或断开后，所有已获取的增强锁立即消失；
- Activity 前台、增强后台、普通后台三种状态下，RDP 持续连接与网络波动恢复符合分级预期；
- 记录短时耗电差异，不将单次短测外推为长期续航承诺。
