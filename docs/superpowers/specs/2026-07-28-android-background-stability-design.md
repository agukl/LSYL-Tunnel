# Android 后台隧道稳定性设计

## 背景

当前 Android 客户端虽然显示常驻的“已连接”通知，但运行状态仍间接依赖前台页面：

- `MainActivity.onResume()` 会触发一次远端刷新。
- `TunnelForegroundService` 每 15 秒执行 `health` 和逐规则检查。
- 任意一次网络超时、切网或短暂不可达都会停止 `TunnelManager`、移除前台通知并结束服务。

因此通知只是状态展示，并未真正代表隧道已由服务独立托管。用户切换到 RDP、锁屏或关闭 LSYL 页面后，短暂网络波动更容易表现为隧道退出且无法自行恢复。

## 目标

1. 用户点击连接后，隧道完全由 `TunnelForegroundService` 持有，不依赖 `MainActivity` 生命周期。
2. LSYL 页面退到后台、从最近任务移除、锁屏或切换到其他应用后，本地监听继续工作。
3. 网络短暂中断时保留服务和本地监听；网络恢复后，新业务连接可以重新建立隧道。
4. Android 因资源压力回收进程后，只要用户没有主动断开，服务恢复时重新加载已保存 Profile 并重建监听。
5. 不使用 `WakeLock`，不要求用户关闭电池优化，不引入定时网络轮询。
6. 提供可定位的连接阶段、全局错误和单规则错误提示。
7. 允许用户以受限文本形式修改正向转发规则，不开放服务端、账号、凭据或 TLS 配置。

## 非目标

- 不实现 VPN、TUN 或系统流量接管。
- 不保证网络切换后已有 TCP/RDP 数据流无缝续传；已有流可能断开，但服务和本地监听不得因此退出。
- 不绕过 Android“强制停止”语义；用户在系统设置中强制停止应用后，不自动恢复。
- 不修改服务端协议、服务端配置或授权模型。
- 不增加持续轮询、保活心跳或高频重试。

## 方案选择

### 方案 A：保留 15 秒检查并增加重试

实现改动较小，但会持续唤醒设备、建立 TLS 连接，并需要处理重试次数和退避状态。它仍把“控制面暂时不可达”错误地等同于“本地监听不可用”，不采用。

### 方案 B：通过 `WakeLock` 保持进程和网络活跃

可能减少部分厂商系统的休眠影响，但会增加耗电，也不能修复当前一次超时就主动结束服务的问题，不采用。

### 方案 C：服务独立托管、事件驱动恢复

由前台服务持有运行时和本地监听，移除定时健康检查；业务连接按需建立 TLS，网络恢复事件只触发一次状态复核。该方案直接消除页面依赖，空闲时没有额外网络流量，是本次采用的方案。

## 生命周期架构

### 组件职责

- `MainActivity`：导入、编辑、连接、断开和展示状态。只发送命令、订阅快照，不持有隧道对象，也不在 `onResume()` 自动刷新远端。
- `TunnelForegroundService`：唯一运行时所有者，持有 `TunnelManager`、网络回调、前台通知和连接意图。
- `TunnelManager`：创建并维护每条 `LocalForward`，汇总监听状态和规则错误。远端连接失败不能停止其他监听。
- `LocalForward`：持续监听 `127.0.0.1:<port>`；每个本地业务连接到来时按需建立 TLS 隧道。单次连接失败只关闭该连接。
- `RuntimeStateStore`：保存结构化运行快照和 `desired_running`，供 Activity 展示及系统回收后的恢复判断。

### 用户连接

```text
点击连接
-> 写入 desired_running=true
-> 启动前台服务并立即显示“正在连接”
-> 加载和本地校验 Profile
-> 绑定全部可用的 127.0.0.1 监听端口
-> 执行一次远端 health/forward_check
-> 发布“已连接”“部分端口不可用”或“等待网络恢复”快照
```

远端初始检查遇到超时、断网或拒绝连接时，服务与已成功绑定的本地监听继续存在。后续本地业务连接仍会按需尝试建立隧道。

证书不匹配、凭据过期、认证失败、Profile 不合法以及客户端/协议版本不兼容属于不可恢复错误：停止全部监听、写入 `desired_running=false` 并保留可操作的失败状态。若全部规则都无法绑定本地端口，也按不可恢复的本地启动失败处理；若只有部分规则绑定失败，则进入 `DEGRADED`，其余规则继续工作。

### 页面生命周期

`MainActivity.onPause()` 和 `onDestroy()` 只解除 UI 订阅，不发送停止或刷新命令。重新打开页面时直接读取服务保存的结构化快照，不通过一次远端请求来判断服务是否存活。

### 系统回收恢复

- 用户主动连接时持久化 `desired_running=true`。
- 用户主动断开、删除 Profile，或出现证书、凭据、认证、版本及不可恢复的本地配置错误时写入 `desired_running=false`。
- 服务使用 `START_STICKY`。收到空 Intent 重建时，仅在 `desired_running=true` 且 Profile 仍有效时重建 `TunnelManager` 和监听。
- 启动和恢复必须幂等；并发或重复的启动命令不得创建重复监听器。
- 用户从系统设置“强制停止”应用时遵循 Android 行为，不尝试绕过。

## 网络恢复

服务通过 `registerDefaultNetworkCallback` 观察默认网络，并增加 `ACCESS_NETWORK_STATE` 权限：

- `onLost`：状态切换为“网络暂不可用，等待恢复”，保留服务和本地监听，不关闭其他仍可工作的网络连接。
- `onAvailable`：在服务串行执行器中合并重复事件，执行一次 `health/forward_check`，恢复可用规则状态。
- 本地业务连接到来时始终允许按需尝试 `open`，不等待网络回调或定时器。
- 不使用固定间隔重试；连续失败不会形成后台网络风暴。

网络回调只作为恢复提示，不作为绝对可达性判断。最终结果仍由实际 TLS/协议请求决定。

## 前台服务类型与耗电

当前 `dataSync` 类型在目标 SDK 35 下不适合无限期隧道，并受到 Android 15 时长限制。服务改为 `specialUse`，声明 `FOREGROUND_SERVICE_SPECIAL_USE` 及明确的 subtype，表示“用户主动启动的持续加密本地端口隧道”。

项目当前通过安装包分发；若未来提交 Google Play，需要同步完成 `specialUse` 前台服务用途声明和商店审核材料。

空闲状态只保留阻塞式本地 `ServerSocket.accept()`、前台服务和系统网络回调：

- 无 15 秒 Handler。
- 无空闲 TLS 心跳。
- 无 `WakeLock`。
- 无电池优化豁免提示。

因此本次修改不会通过提高后台唤醒频率换取稳定性，空闲网络和 CPU 消耗应低于当前版本。

## 状态模型

运行状态不再依赖中文字符串判断。服务发布结构化快照：

- `DISCONNECTED`：用户未要求连接。
- `STARTING`：正在加载 Profile、绑定监听并执行首次检查。
- `CONNECTED`：服务运行，全部规则的本地监听可用，最近检查没有异常。
- `DEGRADED`：服务运行，至少一条规则不可用，其他规则继续工作。
- `WAITING_NETWORK`：服务和监听仍在，最近一次远端请求因网络原因失败。
- `STOPPING`：正在处理用户主动断开。
- `FAILED`：Profile、证书、凭据或协议等不可恢复错误，需要用户操作。

通知栏“已连接”只在前台服务存在且至少一个有效本地监听存活时显示。`WAITING_NETWORK` 和 `DEGRADED` 使用对应文案，不能继续显示陈旧的“已连接”。

每条规则分别记录监听状态和最近一次业务错误。成功建立后续业务流时清除该规则的瞬时网络错误，避免错误状态永久残留。

## 错误处理与交互

首页按顺序展示连接阶段：

```text
读取配置 -> 连接服务端 -> 验证账号 -> 检查转发规则 -> 已连接
```

异常时在状态组件下方展示详情，不用连续 Toast 或模态框打断用户：

| 类型 | 用户提示 | 行为 |
| --- | --- | --- |
| 本地端口占用 | `<规则名>：本地端口 <port> 已被占用` | 仅该规则失败 |
| 无网络或切网 | `网络暂不可用，等待恢复` | 保留服务和监听 |
| DNS 解析失败 | `无法解析服务端地址，请检查当前网络` | 等待网络或手动检查 |
| 连接超时 | `连接服务端超时，等待网络恢复` | 保留服务和监听 |
| 连接被拒绝 | `服务端端口拒绝连接，请联系管理员检查服务状态` | 保留服务和监听 |
| 证书不匹配 | `服务端证书不匹配，请重新导入管理员下发的配置` | 全局失败，停止监听 |
| 凭据过期 | `连接凭据已过期，请重新导入配置` | 全局失败，停止监听 |
| 认证失败 | `账号认证失败，请重新导入配置或联系管理员` | 全局失败，停止监听 |
| 临时封禁 | `登录失败次数过多，当前网络来源已被临时封禁，请稍后重试` | 保留配置，可手动检查 |
| 客户端版本不支持 | `客户端版本不在服务端允许范围内，请联系管理员` | 全局失败，停止监听 |
| 协议版本不一致 | `客户端与服务端协议版本不一致，请联系管理员升级` | 全局失败，停止监听 |
| 账号并发受限 | `<规则名>：账号并发连接已达上限，请稍后重试` | 仅当次业务连接失败 |
| 目标未授权 | `<规则名>：当前账号没有访问该端口的权限` | 仅该规则停用 |
| 目标不可达 | `<规则名>：目标服务暂不可达，请联系管理员检查目标服务` | 仅当次业务连接失败 |

多规则场景只列出异常规则，展示“规则名 + 本地端口 + 原因”，不展示服务端地址、证书信息、密封凭据或 `server_target`。提供用户主动触发的“重新检查”按钮；页面恢复前台本身不触发检查。

## 受限文本配置

文本编辑器只暴露 `forwards`：

```yaml
forwards:
  - name: rdp
    listen_addr: 127.0.0.1:13389
    server_target: 192.168.1.7:3389
```

规则约束：

- 使用 SnakeYAML Engine 的安全加载模式解析为映射和列表，不使用字符串替换或可实例化任意类型的 YAML 构造器。
- `direction` 固定为 `client_to_server`，不在编辑器中显示。
- 只允许 `forwards` 顶层键以及 `name`、`listen_addr`、`server_target` 规则键；未知键和错误层级直接报错。
- `listen_addr` 必须为 `127.0.0.1:<port>`，端口范围为 `1024..65535`，且不可重复。
- `server_target` 必须为有效的 `host:port`，主机部分允许 IPv4 或域名；连接由服务端发起，因此可填写服务端所在网络可达的内网目标。
- 规则名非空且不可重复，规则数量保持不超过 `MAX_MOBILE_FORWARDS`。
- 连接期间禁止保存；用户先断开再编辑。
- 保存前完整解析和校验，失败时指出具体规则和字段，原配置保持不变。
- 保存时只替换 Profile JSON 中的 `forwards`，证书、服务端地址、账号、`client_id`、密封凭据、TLS 和连接参数保持原值。
- 使用同目录临时文件加原子替换，避免异常退出留下半写文件。

服务端仍对账号、方向和精确目标执行最终授权。文本编辑能力不改变服务端安全边界。

## 测试范围

### 单元测试

- 结构化状态的持久化、恢复和中文展示映射。
- 网络异常、协议错误码和 TLS 异常的分类及是否可恢复策略。
- 重复启动幂等，主动断开后不恢复，系统重建且 `desired_running=true` 时恢复。
- 网络丢失不停止 `TunnelManager`，网络恢复事件合并为一次检查。
- 单条业务连接失败不关闭 `LocalForward`；后续成功连接清除瞬时错误。
- 文本配置解析、未知字段、错误层级、端口范围、重复规则和原子保存失败保护。

### 构建与回归

- 执行 Android JVM 单元测试并构建 release APK。
- 执行 Go 全量测试，确认 Profile 导出和服务端协议未回归。
- 真机验证连接后执行：按 Home、划掉任务卡、锁屏数分钟、切换 Wi-Fi/移动网络、进入 RDP，再确认本地端口可重新建立连接。
- 使用 Android Studio Profiler 或 `adb shell dumpsys` 确认后台无固定 15 秒网络请求和 CPU 唤醒。

## 验收标准

1. 通知栏显示“已连接”后关闭 LSYL 页面，至少数分钟内无需保持页面可见即可通过 `127.0.0.1:<port>` 使用隧道。
2. 锁屏和切换应用不改变 `desired_running`，不停止服务或本地监听。
3. 短暂断网后服务不退出；网络恢复或下一次业务访问时可以建立新隧道。
4. 用户主动断开后服务、通知和所有监听均停止，系统不会自动重连。
5. 空闲时不存在定时健康检查、`WakeLock` 或持续重试。
6. 单条规则错误不影响其他规则，错误信息可定位且不暴露服务端目标。
7. 文本配置只能修改转发规则，非法内容不会损坏当前 Profile。
