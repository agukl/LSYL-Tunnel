# 版本发布说明

以下为历史版本变更记录。当前转发配置及兼容边界以[配置参考](../system/config-reference-zh.md)为准，不应将旧版本条目作为现行配置说明。

## 3.6.0

服务端配置结构升为 V2，握手协议仍为 3。Windows 文件版本为 `3.6.0.0`；Android `versionCode` 为 `13`，`versionName` 和握手中的 `client_version` 为 `3.6.0`。

- 标准 Windows 客户端虚拟入口只接受显式 `IPv4:端口`，不再从证书 SAN 自动选择 IP；旧 `:端口` 配置须手工补齐 IPv4，客户端不会静默改写。虚拟地址不要求出现在服务端证书中。TLS 信任与服务端目标授权不变，隧道拨号端口、重复端点及特殊地址限制保留。
- 服务端移除 YAML 的 `compatibility` 区块，协议号固定为 3，仅接纳协议匹配的 3.x 客户端，不再配置客户端版本上下限。旧 V1 配置不能直接启动；3.x 覆盖安装会从新版 V2 模板保留旧监听地址、用户及转发规则，丢弃旧兼容配置。安装失败时恢复旧配置；回退 3.5.0 前也须恢复旧配置。
- 服务端管理台的侧栏、按钮、表格及表单配色向客户端青绿主题对齐，告警和危险操作仍保留独立状态色。
- 转发规则约束统一由核心校验，管理台保留字段定位和反向端口占用探测；客户端安装脚本复用客户端的配置归档命名逻辑，不再手工扫描 YAML。

## 3.5.0

本次按服务端配置项和默认业务连接行为变化升级次版本。Windows 文件版本为 `3.5.0.0`；Android `versionCode` 为 `12`，`versionName` 和协议中的 `client_version` 为 `3.5.0`。握手协议仍为 `3`，客户端与服务端配置结构版本分别保持 `2`、`1`。

- 服务端管理台修复 Wails 窗口拖动区域，并清理不再产生的旧错误提示。
- Android 客户端可保留多份 Profile 及各自证书；导入时可设置本机别名并自动选中新配置。原有单配置继续可用，断开后可从顶部列表切换或二次确认删除；转发编辑移至顶部图标，底部导入按钮使用整行宽度。配置文件与当前配置标识共用原子写入实现。
- 服务端移除默认关闭的单账号业务连接上限、逐连接限速和“用户并发”页；入口层总并发、单 IP 并发及新连速率限制保持不变。旧 3.x 服务端配置覆盖安装时丢弃这些旧字段；无效的 `log_level`、`flow_traffic_log_file` 和旧连接速率别名也不再直接读取。日志文件类别与已有流量统计不变。
- Android 客户端首次登录继续使用原地址，正向转发与规则检查按本地 IPv6 候选质量优先拨号，TCP 失败回退原入口；不新增后台心跳。Win7 轻量客户端行为不变。
- 标准 Windows 客户端覆盖安装后，在新包的活动配置中保留可读出的旧连接用户名；新包的服务端地址、转发、证书和空设备标识不变。旧密码与密封凭据不跨配置复制，登录时重新输入密码；原配置和证书仍按旧地址归档。不兼容的旧配置或归档原样保留、不阻止安装，最终活动配置仍须通过严格校验。
- 服务端覆盖安装改为从新版安装包配置生成 `server.yaml`，保留旧用户、转发规则和主入口监听地址；旧业务入口字段不迁移，其他旧字段也不因结构差异阻止 3.x 升级。无效的保留字段仍阻止安装，预检、备份及失败回滚保持不变。旧密封密钥和自定义运行路径不迁移；升级后客户端可能需要重新输入已保存的登录密码。
- 服务端新增 `ipv6_tunnel_enabled` 开关，在原拨号端口增加 IPv6 隧道监听；多个公网 IPv6 地址由服务端自动公布，客户端在本地评估拨号质量。新建业务流、反向控制、转发检查和探活优先走 IPv6，不可用时回退原入口。旧显式业务入口配置不迁移；旧客户端继续使用原入口，握手协议版本不变。IPv6 质量不上报服务端，也不增加监控状态或日志字段。

## 3.4.0

- Windows 覆盖安装仅迁移已安装 3.x 的配置：文件覆盖前预检、补齐可推导字段并备份；客户端当前及归档配置一并处理，回滚失败保留备份。现场重打客户端安装包前校验配置。
- 运行时只读取当前结构版本（客户端 `2`、服务端 `1`），不再直接读取无版本及更早结构；协议版本仍为 `3`。服务端管理台迁移到 Wails v3，并整理归属查询与窗口交互。

## 3.3.0

本版本调整服务端日志的默认结构和分发内容，并完善标准 Windows 客户端的虚拟入口地址策略，因此按配置及默认行为变更升级次版本。

- 程序版本升级为 `3.3.0`，Windows 文件版本同步为 `3.3.0.0`；Android `versionCode` 递增为 `10`，`versionName` 和 `client_version` 同步为 `3.3.0`。Android 业务逻辑不变。
- 服务端将数据流统计和异常并入业务流水，生产环境使用 request、business、entry-traffic 三类 JSONL；服务日志不再重复镜像流水，只保留运行诊断。旧 `flow-traffic` 文件不删除，旧 `flow_traffic_log_file` 和 `log_level` 配置字段仍可读取，但新配置与 GUI 保存不再写出。
- 服务端安装包不再携带前台调试 CLI 和密码工具；开发构建继续生成，覆盖旧安装时只清理安装目录中的对应旧程序。
- 标准 Windows 客户端虚拟入口允许显式私有 IPv4 和 `127.0.0.1`；公网 IPv4 仍须证书 SAN 授权，回环入口直接监听且不使用提权 helper。其他端的虚拟入口实现不变。
- 协议保持 `protocol_version: 3`，客户端和服务端 `config_version` 分别保持 `2`、`1`，最低兼容客户端版本不变。满足现行地址约束的旧配置可由新程序读取；新模板省略了两个旧服务端必填字段，回退到旧版安装器时会触发兼容检查，不能把新版安装包当作无条件可回退版本。

## 3.2.0

本版本按配置校验行为变化升级次版本，统一转发地址边界，并改进标准 Windows 客户端交互和代码维护结构。

- 程序版本升级为 `3.2.0`，Windows 文件版本同步为 `3.2.0.0`；Android `versionCode` 递增为 `9`，`versionName` 和 `client_version` 同步为 `3.2.0`。
- 回环配置只接受 `127.0.0.1`，`localhost`、`::1`、其他回环别名及 IPv4 映射回环地址明确报错，不再自动兼容或改写。配置读取、保存、导入导出和安装前检查采用相同规则；升级前需手工修正旧写法，涉及 TLS 地址时仍须满足证书 SAN 校验。
- 标准 Windows、Win7 Lite 和 Android 统一转发目标校验：正向目标限定为 `127.0.0.1` 或私有网段 IP 加端口，反向目标限定为 `127.0.0.1:端口`；虚拟入口继续只接受证书授权的非本地 IPv4，客户端配置不由服务端下发或静默修改。
- 标准客户端新增用户主动启用的开机自启，使用当前配置已保存的凭据连接，成功后进入托盘，失败时显示窗口提示；Win7 Lite 和 Android 不增加此功能。
- 标准客户端改用透明原生宿主和 WebView2 页面圆角，移除像素级窗口区域硬裁剪；配置菜单保留图标右键入口。服务端、Win7 Lite 和 Android 的窗口方案不变。
- 修正服务端连接并发名额和活动连接的生命周期，关闭服务时统一回收连接及后台任务；按职责整理隧道核心、管理台页面模块和类型化监控状态，补充统一源码检查入口。
- 协议保持 `protocol_version: 3`，客户端和服务端配置结构分别保持 `2`、`1`，最低兼容版本不变。满足现行地址和授权约束的 3.0.x、3.1.x 与 3.2.0 两端仍可按协议 3 互通；含旧回环写法的配置必须先修正。现有四类业务日志及字段不变。

- 程序版本升级为 `3.1.1`，Windows 文件版本同步为 `3.1.1.0`；Android `versionCode` 递增为 `8`，`versionName` 和 `client_version` 同步为 `3.1.1`，Android 业务逻辑不变。
- 标准客户端和服务端管理台迁移到 WebView2，支持 Windows 10 / Windows Server 2016 及以上桌面环境；Win7 Lite 保留独立原生界面，不依赖 WebView2，服务端 Windows 服务本身也不依赖该运行时。
- 双端安装器在缺少 WebView2 Runtime 时自动补装，显示安装状态，失败则停止安装；默认引导安装器需要联网，支持构建时指定微软离线完整安装器，已有运行时则跳过。
- 客户端配置菜单改为明确的单次点击入口；服务端补充未保存配置的刷新确认，修正日志表格滚动，并优化下拉选项与列宽操作。
- 双端前端资源统一独立到 `front` 并嵌入 exe；GUI 按窗口、HTTP、路径和日志职责整理，合并长期文档并清理旧阶段计划，不增加前端构建工具链。
- 协议保持 `protocol_version: 3`，客户端和服务端配置结构分别保持 `2`、`1`，最低兼容版本不变。原有合法配置可继续使用，3.0.x、3.1.0 和 3.1.1 两端继续按协议 3 互通；现有日志类型和字段不变。

## 3.1.0

本版本在保持协议 3 兼容的前提下，修正 Windows 客户端瞬时连接错误处理，并增加客户端配置备注提示。

- 程序版本升级为 `3.1.0`，Windows 文件版本同步为 `3.1.0.0`；Android 客户端 `versionCode` 递增为 `7`，`versionName` 和 `client_version` 同步为 `3.1.0`。
- LSYL 握手协议保持 `protocol_version: 3`，服务端最低兼容客户端版本保持 `3.0.0`；3.0.x 与 3.1.0 两端可继续按协议 3 互通。
- Windows 客户端不再把证书持有前置门和 TLS 阶段的超时、EOF、连接重置或服务端 TLS 异常误判为永久证书错误；瞬时故障进入既有重连流程，明确的证书过期、地址不匹配和不受信任仍会终止连接。
- 客户端配置新增可选 `remark` 字段，仅在 Windows 客户端切换配置时显示为“服务端地址 · 备注”，不参与连接、认证、证书校验或转发协议。旧配置可直接使用；包含该字段的配置要求 3.1.0 或更高版本客户端。
- 安装器兼容检查将空 YAML 备注 `remark:` 视为未填写，不再阻止覆盖安装；映射、列表、未知字段和错误层级仍会被严格拒绝。
- Win7 轻量客户端导入 `.lsylprofile` 后使用目标机器的本机名作为 `client_id`，不再沿用导出电脑的日志标识；密封凭据不再与该非安全字段耦合。
- 客户端配置结构保持 `config_version: 2`，服务端配置结构保持 `config_version: 1`，现有日志文件、字段及服务端配置语义不变。

## 3.0.0

本版本在公网 TLS 入口前增加证书持有前置门，按不兼容协议升级发布。

- 程序版本升级为 `3.0.0`，Windows 文件版本同步为 `3.0.0.0`；Android 客户端 `versionCode` 递增为 `6`，`versionName` 和 `client_version` 同步为 `3.0.0`。
- LSYL 协议升级为 `protocol_version: 3`。服务端先发送一次性挑战，客户端使用预置 `server.crt` 的规范证书内容生成证明；通过后才开始 TLS 握手，未持有配套证书的直接 TLS、HTTP 和通用扫描不会收到服务端 TLS 证书。
- 前置门覆盖标准 Windows 客户端、Win7 轻量客户端和 Android 客户端，不新增配置字段、密钥文件或日志类型；现有四类业务日志及字段保持不变。
- 客户端配置结构保持 `config_version: 2`，服务端配置结构保持 `config_version: 1`。当前分发默认配置要求程序版本 `3.0.0`，客户端 `tls.ca_cert_file` 在所有 TLS 校验模式下都必须存在。
- 协议 3 不提供 TLS 优先回退，2.x 客户端不能连接 3.0.0 服务端，3.0.0 客户端也不能连接 2.x 服务端。旧服务端配置若显式保留 `compatibility.protocol_version: 2`，严格兼容检查会阻止覆盖安装，升级前必须改为 `3`，并将最低客户端版本调整为 `3.0.0`。
- 该机制不是 mTLS，`server.crt` 也不是客户端身份私钥；持有该文件的程序仍可通过前置门，后续账号认证、转发授权、入口限流和业务防护继续生效。若旧版服务曾公开提供 TLS 或旧安装包已公开分发，切换时应同步轮换服务端证书和客户端预置证书。

## 2.2.0

本版本在保持协议和配置兼容的前提下，强化 Android 后台连接、服务端封禁正确性、运行性能和客户端交付安全性。

- 程序版本升级为 `2.2.0`，Windows 文件版本同步为 `2.2.0.0`；Android 客户端 `versionCode` 递增为 `5`，`versionName` 和 `client_version` 同步为 `2.2.0`。
- LSYL 握手协议保持 `protocol_version: 2`，客户端配置结构保持 `config_version: 2`，服务端配置结构保持 `config_version: 1`；现有 2.1.0 配置可直接使用，2.1.x 客户端和服务端继续按原协议互通。
- Android 隧道生命周期从界面生命周期中解耦，补充网络恢复、状态持久化、通知状态同步、文本转发配置和可选增强后台模式；默认后台模式保持较低资源消耗，增强模式由用户主动启用。
- 服务端启动和运行期间会保护近期成功登录 IP，避免已确认的正常来源被写入永久封禁；临时封禁响应和批量永久解封流程同步修正。
- 运行时改用标准库 PBKDF2，缓存 Windows 客户端 TLS 配置并复用虚拟转发辅助会话；服务端最近事件使用有界环形缓冲，日志复用序列化结果，IP 表清扫从每次新来源调整为定时或容量触顶执行。
- 默认客户端打包和现场重新生成安装器都会清空 `client_id`；现场客户端 kit 的原始配置同步保存为空值，目标机器首次成功登录后再使用本机名。
- 服务端 GUI 调整导航顺序并统一“归属分析”命名，不改变配置字段或管理接口。

## 2.1.0

本版本升级客户端配置结构并收紧标准 Windows 客户端的 IP 接管边界。

- 程序版本升级为 `2.1.0`，Windows 文件版本同步为 `2.1.0.0`；Android 客户端 `versionCode` 递增为 `4`，`versionName` 和 `client_version` 同步为 `2.1.0`。
- LSYL 握手协议保持 `protocol_version: 2`，服务端默认仍允许 2.0.x 客户端连接；2.1.0 客户端也可以连接 2.0.x 服务端。
- 客户端配置结构升级为 `config_version: 2`，默认要求 `requires.min_client_version: "2.1.0"`。新客户端继续兼容严格合法的 V1 和无版本旧配置；V2 配置会被旧客户端明确拒绝。
- 客户端启动、配置切换和覆盖安装共用严格 YAML 校验：未知字段、错误层级、重复字段、V1/V2 缺失必填结构及无效转发语义会直接阻止使用，不再静默忽略旧虚拟 IP 字段。
- 严格校验继续接受旧版和未登录配置使用的空凭据对象 `saved_credential: {}`；非空凭据仍必须包含完整字段，避免覆盖安装误判合法配置。
- Windows IP 接管按规则独立管理，随机桥接端口只绑定 `127.0.0.1`，流映射使用有界内存表；刷新不会把未授权虚拟规则恢复成普通监听，单条规则停止或异常不影响其他规则，并会先撤销 WinDivert 过滤再释放桥接端口。
- 提权进程只加载安装目录内通过固定 SHA-256 校验的 WinDivert 2.2.2 DLL 和驱动，并通过带随机令牌的 IPv4 回环控制通道向父进程报告状态，不依赖当前 Windows 账号的缓存目录。
- 客户端覆盖安装会跳过内容未变化的 WinDivert 运行库，避免已加载驱动导致覆盖失败；运行库确有变化且仍被占用时，安装器会安排重启后完成替换。
- 一键发布在旧 `dist` 目录无法整体重命名时会回退到原地镜像刷新；发布失败会正确返回非零退出码，不再保留旧安装包却显示成功。

- 服务端强化入口资源保护：失败追踪和连接来源追踪均增加过期清扫、容量上限、逐出统计；入口异常日志改为有界异步写入，永久封禁命中仅记录聚合事件。

- Android 客户端使用有上限工作线程池，任一方向复制结束即关闭对端连接，避免半关闭连接长期占用资源。

## 1.1.0

本版本聚焦服务端防护、日志目录收口、GUI 运维入口和 Windows 发布链路。

### 服务端防护

- 增加入口连接层内存限制：全局并发、单 IP 并发、单 IP 新连接速率。
- 增加业务数据层内存限制：单账号并发连接和每连接传输速率。
- 将永久封禁命中、非 TLS、HTTP 探测等明显无效请求前移到入口连接层处理。
- 正常放通连接仍由后续认证、业务控制和数据流日志记录，入口层不额外落正常放通流水。

### 服务端 GUI

- “服务安全”页增加入口连接层并发和速率限制配置。
- 新增“用户并发”页，用于查看和调节单账号并发、每连接速率限制。
- 运行总览去掉监控地址统计块，减少重复信息。

### 日志与目录

- 生产服务端日志按业务类型拆到 `logs/request`、`logs/business`、`logs/entry-traffic`、`logs/flow-traffic`、`logs/service`。
- 生产持久化数据继续收口到 `data`，例如运行状态和永久封禁名单。
- 源码开发运行产物继续使用 `runtime/data` 和 `runtime/logs`，避免和分发包路径混用。

### 发布链路

- 一键发布入口保持为根目录 `release.cmd`。
- 打包脚本在旧 `dist` 目录被占用时支持原地刷新，减少 Windows 资源管理器占用导致的失败。
- `release.cmd` 默认对安装包内主线 Go 二进制启用 `garble` 混淆和 `-trimpath -ldflags "-s -w"` 瘦身。
- Windows exe 版本资源、manifest、Inno 安装包版本和自检脚本统一到 `1.1.0 / 1.1.0.0`。
